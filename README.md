# Новини Польща

Бот для Telegram-каналу, який сам знаходить свіжі новини про Польщу, відбирає
найважливіші для іноземців, переказує їх українською, малює картинку й публікує.
Працює на GitHub Actions за розкладом: комп'ютер для цього не потрібен.

## Як це працює

1. Бот читає RSS-стрічки польських медіа (список у `config.py`).
2. AI (Gemini або Claude) вибирає найважливіші новини, яких ще не було в каналі. Скільки саме,
   вирішує сам: коли нічого вартого — жодної, зазвичай 1–2, у насичені години — до 6.
3. Для кожної бот завантажує повний текст статті, і AI пише короткий пост своїми словами.
4. Бот малює картку із заголовком і публікує її з підписом та посиланням на джерело.
5. Список опублікованого зберігається в `data/posted.json`, щоб новини не повторювались.

## Встановлення

Перед цим мають бути готові канал, бот-адмін, ключ Gemini, приватний репозиторій
і три секрети: `TELEGRAM_BOT_TOKEN`, `GEMINI_API_KEY`, `TELEGRAM_CHANNEL`.

1. Розпакуй архів. У репозиторії на GitHub натисни **Add file → Upload files**,
   перетягни туди **весь вміст** розпакованої папки (разом із папками `.github`,
   `fonts`, `backgrounds`) і натисни **Commit changes**.
2. Перевір, що в репозиторії з'явився файл `.github/workflows/news.yml`. Якщо папки
   `.github` немає, створи файл вручну: **Add file → Create new file**, у полі назви
   введи `.github/workflows/news.yml`, встав вміст файлу з архіву й збережи.
3. Відкрий вкладку **Actions → Новини Польща → Run workflow**. Для першої перевірки
   можна поставити галочку «Тестовий запуск без публікації». Тоді бот перевірить токен
   і права в каналі, нічого не публікуючи, і покаже в лозі, що б він опублікував.
   Картинки й тексти постів можна скачати внизу сторінки запуску: **Artifacts → preview**.
4. Запуск триває 1–3 хвилини. Зелена галочка означає, що все гаразд. Червоний хрестик —
   відкрий запуск і подивись лог кроку «Зібрати й опублікувати новини».

Далі бот працює сам: щогодини з 06:17 до 23:17 (влітку) перевіряє новини й публікує
найважливіші, але не більше 30 постів за день. Якщо запуск упаде,
GitHub надішле лист на пошту.

## Розклад

Розклад задається у файлі `.github/workflows/news.yml`, рядок `cron`. Час там у UTC:
у Польщі влітку це +2 години, взимку +1.

| Що хочеш | Рядок cron |
|---|---|
| Щогодини з 06:17 до 23:17 (літо), зараз | `"17 4-21 * * *"` |
| Щогодини цілодобово | `"17 * * * *"` |
| 4 рази на день | `"17 5,9,13,17 * * *"` |

GitHub інколи запускає заплановані задачі із запізненням на 10–30 хвилин, це нормально.

Для приватних репозиторіїв GitHub дає 2000 безкоштовних хвилин Actions на місяць. Запуск
щогодини вдень займає приблизно 600–1100 хвилин, тож запас є. Цілодобовий розклад
витрачає більше. Скільки використано, видно в Settings → Billing and plans.

### Якщо GitHub пропускає запуски за розкладом

На безкоштовному тарифі GitHub запускає задачі за розкладом без гарантій: може запізнитися
чи пропустити запуск. Надійніше, щоб бота щогодини «будив» зовнішній сервіс cron-job.org:

1. На GitHub створи ключ: https://github.com/settings/personal-access-tokens/new →
   **Only select repositories** → `Info_bot` → **Permissions → Actions: Read and write**
   → **Generate token**. Скопіюй його (`github_pat_…`) і нікому не показуй.
2. На https://console.cron-job.org створи завдання:
   - **URL:** `https://api.github.com/repos/romakvasha/Info_bot/actions/workflows/news.yml/dispatches`
   - **Schedule:** Custom, хвилина `17`, години `6–23`, часовий пояс `Europe/Warsaw`;
   - **Advanced → Request method:** `POST`;
   - **Headers:** `Authorization: Bearer <ключ>`, `Accept: application/vnd.github+json`,
     `X-GitHub-Api-Version: 2022-11-28`, `Content-Type: application/json`;
   - **Request body:** `{"ref":"main"}`.
3. **Test run** має показати відповідь `204`, а в Actions з'явиться новий запуск.

Розклад GitHub можна лишити як запасний: якщо два запуски збіжуться, другий дочекається
першого й повторів не буде.

## Налаштування

Усе основне лежить у `config.py`:

- `POSTS_PER_RUN` — скільки новин максимум за один запуск (AI часто бере менше);
- `MAX_POSTS_PER_DAY` — денний максимум постів, запобіжник від спаму й вичерпання ліміту Gemini;
- `RSS_FEEDS` — джерела (назва й адреса RSS), можна додавати й видаляти;
- `TOPICS` — теми, емодзі й хештеги;
- `CHANNEL_TITLE` і `ADD_CHANNEL_LINK` — підпис на картинці й посилання на канал у постах.

- `RATES_ENABLED` і `RATES_HOUR` — щоденна картка з курсом валют (о 14:00 або в перший запуск
  після): долар → злотий від NBP, долар → гривня й злотий → гривня від НБУ. Курси — у `rates.py`.

Стиль постів і критерії відбору новин — у `prompts.py`, звичайним текстом.
Редагувати файли можна прямо на GitHub (іконка олівця).

## Картинки

Без додаткових файлів картка має білий верх із заголовком і червону смугу, як польський
прапор. Щоб використовувати фото, поклади в папку `backgrounds` файли з назвами тем
(`work.jpg`, `legalization.jpg` тощо). Подробиці — у `backgrounds/README.md`.

## Перехід на Claude

1. Створи ключ у Claude Console і додай секрет `ANTHROPIC_API_KEY`.
2. У `config.py` зміни рядок на `AI_PROVIDER = "claude"`.

## Тест на своєму комп'ютері

Потрібен Python 3.10 або новіший. У PowerShell:

```powershell
cd шлях\до\novyny-polshcha
python -m pip install -r requirements.txt
python card.py                      # приклади карток у папці preview/, ключі не потрібні
$env:GEMINI_API_KEY = "твій_ключ"
python main.py --dry-run            # повний прогін без публікації, результат у preview/
```

## Якщо щось не працює

| Повідомлення в лозі | Що зробити |
|---|---|
| `Не задано секрети…` або `Telegram не перевірено` | Перевір назви секретів у Settings → Secrets and variables → Actions. Секрети прив'язані до репозиторію: у новому репозиторії їх треба додати знову |
| `Unauthorized` | Токен бота неправильний: створи новий у @BotFather через /token |
| `chat not found` | `TELEGRAM_CHANNEL` має бути адресою публічного каналу з @ |
| `not enough rights`, `not a member`, `inaccessible` або `не може публікувати` | Додай бота адміністратором каналу з правом публікації |
| `API key not valid` | Перевір секрет `GEMINI_API_KEY` |
| `AI зараз недоступний, спробую наступного запуску` | Gemini перевантажений або вичерпано денний ліміт. Нічого робити не треба: через годину бот спробує знову |
| `жодна модель Gemini не відповіла` з червоним хрестиком | Постійна помилка, найчастіше неправильний ключ. Перевір секрет `GEMINI_API_KEY` |
| `джерело недоступне` | Одне джерело не відповіло, бот працює з рештою. Якщо так щодня, заміни його в `config.py` |

Файл `data/posted.json` — це пам'ять бота. Не видаляй його, інакше бот може
повторно опублікувати новини за останню добу.
